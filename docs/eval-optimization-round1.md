# remove_001 评测优化实验：第 1 轮

## 实验目标

在不增加主 Agent 工具数量的前提下，减少无效探索、错误后的重复尝试，并让多轮评测共享 token 预算。

## 本轮改动

### 承接的评测正确性修复

- 将所有轮内 `hard_checkers` 纳入最终评测结果，避免后续轮次掩盖前置任务失败。
- 为源码同步增加 `file_not_contains`，同时检查新组件标识存在、旧 `CompElement` 标识不存在。
- 增加 `budget_exceeded`、`budget_finalized` 状态及批次统计。
- 多轮 Agent 共享累计 token 用量。

### 本轮优化

- 系统提示增加连续多步任务的执行约束：只读取命名目标、编辑后立即验证、错误后切换路径、状态查询不重新探索。
- 强化 bash 工具描述：文件修改优先使用 `read_file` / `write_file` / `edit_file`，禁止通过 Python、sed、pip 或解释器探测完成修改。
- 强化 `edit_file` 描述，提示使用精确替换并立即验证。

## 评测结果

用例：`trace-3-1-component-element-continuous-remove-001`

| 指标 | 第 1 轮 |
|---|---:|
| 状态 | `budget_finalized` |
| 通过 | 否 |
| 得分 | `0.1163` |
| 耗时 | `68.8s` |
| 工具调用 | `16` |
| token 统计 | `102,949` |

### 轮次情况

- 第 1 轮：问候，无工具调用。
- 第 2 轮：读取组件名称，2 次工具调用，轮内校验通过。
- 第 3 轮：尝试处理 UML 变更，14 次工具调用后进入 `reserve_finalization_empty_response`，未完成修改。
- 第 4～7 轮：由于共享预算已进入收尾，只生成文本或文本化工具调用，没有实际工具执行。

最终校验中：UML 结构和 pytest 通过，但组件重命名、源码同步、无关文件删除以及自动审核校验未通过。

## 结论

本轮显著降低了无效工具调用和耗时，但优化过度偏向“快速停止”：Agent 在第 3 轮探索成本较高后过早进入预算收尾，导致后续任务没有执行。下一轮应减少第 3 轮的上下文/探索成本，并让 Agent 更快采用精确编辑路径。
