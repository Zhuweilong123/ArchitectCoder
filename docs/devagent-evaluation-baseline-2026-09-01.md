## 基线结论

1. 基础能力和大部分 P0 修改链路稳定，Baseline 用例达到全通过。
2. P0 仍有一个真实功能缺口：有限值输入校验未闭环，应作为第一优先级修复目标。
3. P1 UML 类任务是当前主要瓶颈：4 个用例超时，且消耗了本轮绝大多数执行时间和 token。
4. P2 的预算保护用例通过，但损坏 UML 场景仍无法在时限内完成，说明异常恢复和停止条件需要单独优化。
5. 后续比较版本时，至少同时跟踪通过率、超时率、平均得分、P0 通过率、P1 UML 超时率、累计 tokens 和 Tool Calls；不能只看总平均分。
