# Trace 回放使用手册

> 面向日常使用的操作说明。设计背景与架构见 [`trace-replay-design.md`](./trace-replay-design.md)。

## 1. 快速开始

1. 启动后端（`backend/`）与前端（`frontend/`，`npm run dev`）。
2. 点顶部工具栏的 **「Trace」** 按钮，打开 Trace 回放抽屉。
3. 左侧选一个会话，右侧即可查看该会话的完整时间轴。
4. 点 **「回放执行」** 离线重跑一遍，核对结果是否与当时一致。

## 2. 打开 Trace 面板

工具栏第 3 行（LLM 操作区）「AI 助手」右侧有 **「Trace」** 按钮（历史图标）。

抽屉分两块：

- **左侧 · 会话列表**：每个 `session_id` 一行，显示事件数、文件大小、开始时间。按修改时间倒序。顶部「刷新」重新扫描。
- **右侧 · 时间轴**：当前选中会话的事件树。

## 3. 查看会话 trace

时间轴按「**轮次**」分组（一次 `user_message` 即一轮），轮次内是三类卡片：

| 卡片 | 内容 |
|---|---|
| 🤖 **LLM** | 模型、span_path、token 用量、耗时；展开看 Prompt 与 Response |
| 🔧 **工具** | 工具名、耗时；展开看参数与返回 |
| Step / 完成 / 错误 | ReAct 步、最终答案、错误信息 |

**自动播放**：点「自动播放」后逐条高亮并自动滚动，每 700ms 一条，模拟当时的执行节奏；「暂停」/「重置」控制。

**展开查看**：点 LLM / 工具卡片上的 `Prompt` / `Response` / `参数` / `返回` 折叠项，查看原始内容（长文本已截断，末尾标注 `+N 字符`）。

## 4. 执行回放

点抽屉头部 **「回放执行」** 按钮。旁边 `Segmented` 选择模式：

| 模式 | 行为 | 何时用 |
|---|---|---|
| **Mock**（默认） | 全模拟：不调 LLM、不执行工具，纯离线确定性重放 | 回归验证、bug 复现、零成本调试 |
| **Rerun(真LLM)** | 真调 LLM，工具仍按记录 mock | 模型/提示词 A/B、度量漂移 |

> ⚠️ Rerun 会真实调用 LLM（消耗 API、有延迟）。工具仍 mock，无副作用。

执行完弹窗显示结果（见下一节）。

**结果缓存**：回放结果按 `session_id + 模式` 缓存到浏览器 localStorage。再次点「回放执行」若命中缓存，会**直接展示上次结果而不重新执行**；结果弹窗里的「重新执行」按钮可强制重跑。关闭抽屉、甚至刷新页面后再打开，仍能看到上次结果（命中缓存时摘要行会显示灰色「上次结果」标签）。

## 5. 解读回放结果

弹窗顶部：

- **绿色 Alert「回放完全一致」**：所有轮次最终答案与记录逐字匹配，且（Mock 模式下）LLM/工具调用数一致。
- **黄色 Alert「回放存在不一致」**：有轮次答案不同或回放中断。

中间一行统计：模式、LLM 记录次数、工具调用数（`已消费/记录`）。

**每一轮点开可见**：

- ✅ **匹配**：绿色「内容一致」+ 完整答案。
- ❌ **不匹配**：先给**逐词 diff**（红=记录/删除线，绿=回放/新增），再给「记录答案（当时）」与「回放结果（现在）」两侧完整文本。
- ⚠️ **回放中断**：红条显示中断原因（如 `trace 仅记录 N 次工具返回，已耗尽`）。

### 5.1 结果意味着什么

- **Mock 模式全匹配** → 回放引擎与当时执行的控制流完全一致，可放心把这段 trace 当回归基线。
- **Rerun 模式不一致** → **预期现象**。LLM 非确定，重跑答案大概率变化。逐词 diff 帮你量化「这次与上次差在哪」。
- **Mock 模式不匹配 / 中断** → 通常是回放与记录不一致（罕见，见设计文档「已知边界」），值得排查。

## 6. 命令行直接回放（可选）

无需打开 UI，在 `backend/` 目录下：

```bash
cd backend
python -c "
import asyncio
from app.trace.replay import replay_agent_session

async def main():
    r = await replay_agent_session('20260813_232810', mode='mock')  # 或 mode='rerun'
    print('all_matched:', r['all_matched'])
    print('llm:', r['llm_calls'], '/', r['llm_total'], '| tool:', r['tool_calls'], '/', r['tool_total'])
    for t in r['turns']:
        print(' ', 'MATCH' if t['matches'] else 'DIFF ', t['user_message'][:30])

asyncio.run(main())
"
```

HTTP 接口：

```bash
curl -X POST 'http://localhost:8001/api/trace/20260813_232810/replay?mode=mock'
```

## 7. 常见问题

**Q：左侧会话列表是空的？**
后端未启动，或 `temp/chat_log/` 下暂无 `trace_*.jsonl`。先跑一次「AI 助手」对话或「全局优化」生成 trace，再点「刷新」。

**Q：trace 文件在哪？**
`temp/chat_log/trace_{session_id}.jsonl`。会话跨连接复用，同一 session 会持续追加到同一文件。

**Q：为什么 Rerun 总是「不一致」？**
正常。Rerun 就是真调 LLM 重跑，答案几乎不会逐字相同。需要确定性校验请用 **Mock** 模式。

**Q：会话里有多轮对话，回放哪几轮？**
默认整段会话逐轮回放（按 `user_message` 分隔），结果逐轮列出。

**Q：能只回放某一条 trace 里的工具而不真执行吗？**
能——Mock 模式下工具全部按记录返回，不会产生任何副作用。

**Q：为什么点「回放执行」没有重新跑？**
因为命中了上次的缓存结果（摘要行会显示「上次结果」标签）。点结果弹窗里的「重新执行」即可强制重跑。
