# 聊天任务与连接生命周期

任务属于会话，WebSocket 负责订阅事件和发送控制命令。连接断开不再取消任务、释放执行租约或清理待审核请求；主动停止才取消当前执行并保存可恢复检查点。

## 模块职责

- `runtime/agent_runtime.py`：保留会话与单写入执行租约。
- `services/chat_connection.py`：保留任务引用、停止标志、工作区路径、待审核关联；管理可替换订阅连接、事件序号与补发缓存。
- `services/chat_session.py`：处理会话命令，串行启动任务；主动停止后确认停止，审核回复继续投递给原任务。
- `services/agent_execution.py`：执行与检查点管理，事件通过会话投递层发送。
- 前端聊天连接服务：自动重连、携带事件游标、去重，断线期间排队停止或审核回复。

## 用户行为

运行时发送按钮切换为停止。点击停止后显示正在停止，收到后端确认后恢复发送；后续消息可沿用检查点继续。断线时保持任务和审核状态，展示重连提示。重连后补收遗漏事件，不自动启动第二个 Agent。

新页面没有事件游标时，仅同步当前进度、待审核请求与终止结果，避免重新执行历史设计渲染事件。运行任务尚未结束时，状态查询不会发送终止事件。

每次连接都独立同步当前任务的完整进度快照，包括全部已执行轮次和工具摘要；前端按步骤号合并后续事件。事件游标只控制增量事件补发，不作为前端已经保留进度列表的证明。完成结果已经显示时，快照补齐其步骤记录，不重复追加结果。

## 范围与边界

执行引用与事件缓存保留在服务进程内。缓存最多 2000 条事件，并按 16 MiB 控制体积（单条超大事件保留）；补发窗口过期时提示用户查看 trace。事件 epoch 区分服务实例，避免旧游标丢弃新实例事件。

本机制处理同一后端进程内的网络断线、重连与页面刷新。后端重启后的任务继续使用持久化检查点恢复机制，不自动重放已经执行的工具操作。多进程部署需要共享执行调度和事件存储，或保证同一会话路由到其执行进程。
