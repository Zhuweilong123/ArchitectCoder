# remove_001 评测优化实验：第 3 轮

## 实验目标

在不增加主 Agent 工具数量的前提下，减少重复工具 schema 和参数说明占用的上下文预算，让有限预算更多用于实际编辑和验证。

## 本轮改动

- 在工具注册表增加紧凑 schema 生成：保留工具名、调用参数结构和类型，压缩重复的函数描述，并移除参数描述。
- ReAct Agent 首次请求使用完整 schema；首次工具调用后使用紧凑 schema；最终收尾阶段不再发送工具 schema。
- 增加紧凑 schema 的单元测试，确保调用形状保留且参数说明被压缩。
- 更新 Agent prompt 版本为 `3.1-r3`。

主 Agent 工具数量未增加，也未启用子代理。

## 评测结果

用例：`trace-3-1-component-element-continuous-remove-001`

| 指标 | 第 3 轮 |
|---|---:|
| 状态 | `budget_finalized` |
| 通过 | 否 |
| 得分 | `0.1628` |
| 耗时 | `55.0s` |
| 工具调用 | `20` |
| token 统计 | `99,040` |

### 轮次情况

- 第 1 轮：问候，无工具调用。
- 第 2 轮：组件查询，3 次工具调用。
- 第 3 轮：12 次工具调用，仍未完成 UML 编辑、源码同步和清理。
- 第 4 轮：5 次工具调用后进入 `reserve_finalization_empty_response`。
- 第 5～7 轮：只进入收尾状态，没有完成剩余任务。

最终校验中，UML 有效性、组件名称和 pytest 通过；源码同步、旧标识清理、临时文件清理以及自动审核校验未通过。

## 与第 2 轮对比

- 耗时：`61.5s → 55.0s`，减少约 6.5 秒。
- token：`100,123 → 99,040`，减少 1,083。
- 工具调用：`22 → 20`，减少 2 次。
- 得分保持 `0.1628`，任务仍未完成。

## 结论

压缩 schema 能继续降低耗时和 token 消耗，但没有解决执行顺序和收尾阶段的完成问题。本用例当前瓶颈已经从“工具说明过长”转为“在预算收尾前完成一组连续编辑、同步和验证动作”。下一阶段应考虑更强的任务级执行编排，例如为连续任务提供共享的明确检查点，必要时再评估受限的子代理分工。
