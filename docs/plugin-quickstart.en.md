# Plugin quickstart: from local checks to execution history

[中文](plugin-quickstart.md) · [Development toolkit](plugin-development.md) · [Discovery and configuration](plugin-discovery.md)

Use the bundled `task_notes` plugin to connect a framework capability to ArchitectCoder's public phases and inspect its recorded execution. No core changes are required.

## Explore first, without installing anything

Download the [English architecture HTML](media/plugin-demo/plugin-architecture-en.html) or [中文 HTML](media/plugin-demo/plugin-architecture-zh.html) and open it in a browser. On a GitHub file page, choose **Download raw file** and save it as `.html`; GitHub's file page does not run the viewer.

Try these actions:

1. Inspect the main flow, including the phases before and after model calls and tool execution.
2. Click `task_notes` in the plugin list to open its organization graph and details.
3. Search for `task_notes.describe` to inspect its on-demand interface and default `prepare` phase.
4. Search for `task_notes.run_start` to inspect its run-start observer.
5. Return to **Main flow** and click **Expand all**. The same button becomes **Collapse all**.

## 1. Understand the smallest plugin

Inspect [plugin.json](../examples/plugins/task_notes/plugin.json) and its [implementation](../examples/plugins/task_notes/__init__.py). There are two capabilities:

| Capability | Binding | Trigger | Expected result |
|---|---|---|---|
| `describe()` | `service`, default phase `prepare` | An explicit interface request | Returns `Task notes example` |
| `observe_start(context)` | `observer`, phase `run_start` | The main flow enters the run-start phase | Writes a `plugin_example` event to the current Trace |

Phase contributions run when their phase is dispatched. Services run only when requested. Declaring `describe` does not expose a model tool or run it at every `prepare` phase. Skills provide reusable model guidance; plugins extend framework capabilities.

## 2. Verify locally, without starting the application or configuring a model

Use a Python environment with the backend dependencies installed. Run all commands from the **repository root**. See [README setup](../README.md#quick-start) for installation.

Check the actual interface:

```shell
python backend/plugin_dev.py check examples/plugins/task_notes --instantiate --output temp/plugin-demo-check.json
```

Expect `status=passed`, empty `diagnostics`, and `implemented=true` for `describe`. `--instantiate` constructs the example Provider and checks its interfaces, then invokes supported resource cleanup.

Request the service explicitly:

```shell
python backend/plugin_dev.py run examples/plugins/task_notes --method describe --output temp/plugin-demo-describe.json
```

Expect `result` to be `Task notes example`. The `events` array includes a record with `contribution_id=task_notes.interface.describe`, `mode=service` and `status=executed`.

Trigger the phase observer:

```shell
python backend/plugin_dev.py run examples/plugins/task_notes --stage run_start --output temp/plugin-demo-run-start.json
```

Expect `status=passed` and `provider_instantiated=false`. Events include the plugin's `plugin_example` and the scheduler's executed `task_notes.run_start` record. The observer does not need a Provider instance; `result=null` is expected.

These JSON reports use an independent local scheduling context and do not appear in the application's chat Trace list. IDs and durations change on each execution.

## 3. Load the plugin and inspect a task in the application

Configure `backend/.env`:

```dotenv
PLUGIN_ROOTS=["../examples/plugins"]
AGENT_TRACE_ENABLED=true
AGENT_TRACE_PROVIDER=extensions.trace:create
```

Append the example path if `PLUGIN_ROOTS` already contains other roots. Application paths are relative to `backend/`; CLI paths above are relative to your current directory. Configure a model, restart the backend and start the application following the [README](../README.md#quick-start).

1. Click **Plugin architecture** in the toolbar. Find `task_notes`, check that its declaration status is **Discovered**, and inspect its two contributions. Discovery does not imply Provider instantiation.
2. Open [`examples/quickstart`](../examples/quickstart/) as the workspace. Ask the AI Assistant: “Briefly explain what this project does. Analyze only; do not modify files.” This step calls your configured model.
3. After the task finishes, open **Plugin architecture → Execution history**, click **Refresh records**, and select the new session and task.
4. Locate `task_notes.run_start` in the step list. Inspect `observer`, `executed`, `plan_id`, plugin version and duration. The graph expands and highlights its contribution; use **Previous** and **Next** to inspect adjacent records.
5. Use **Export HTML** in the panel to share your own system's current architecture and display state offline.

This task triggers the run-start observer. The local check demonstrates the `describe()` call; sending a chat message does not automatically invoke that service.

For a new plugin under an already configured root, use **Discover plugins**. Adding a root for the first time, or changing an existing plugin's code or configuration, requires a backend restart.

## 4. Create your own plugin (optional)

After completing the example, generate a separate starter:

```shell
python backend/plugin_dev.py new demo_notes --root temp/plugin-demo-scaffold
python backend/plugin_dev.py check temp/plugin-demo-scaffold/demo_notes --instantiate
python backend/plugin_dev.py run temp/plugin-demo-scaffold/demo_notes --method echo --input temp/plugin-demo-scaffold/demo_notes/smoke.json
python backend/plugin_dev.py run temp/plugin-demo-scaffold/demo_notes --stage prepare
```

Expect `plugin.json`, `__init__.py`, `smoke.json` and `README.md`. The following three commands should return `passed`, and `echo` returns an object containing `text=hello`. `new` never overwrites a directory: reuse an existing starter or choose a different name when repeating the exercise.

This temporary starter is not loaded in the application yet. Add its parent directory to `PLUGIN_ROOTS` and restart when ready; see the [development toolkit](plugin-development.md) for details.

## Troubleshooting

| Symptom | Check |
|---|---|
| `task_notes` is absent | Check `PLUGIN_ROOTS` paths and JSON format; restart after first configuring the root |
| Provider is not instantiated | Phase observers do not create Providers; use local `--method describe` to check its instance and interface |
| Session has no lifecycle records | Enable Trace and select a new task run after updating the backend and loading the plugin |
| A historical step is not highlighted | Its plan differs from the current plan or has no ID; details remain available. Run a new task for this demo |
| `check` or `run` fails | Read `diagnostics` and confirm that your Python environment has the backend dependencies |
| GitHub shows HTML source | Download the raw file and open it in your local browser |

See the [asset notes](media/plugin-demo/README.md) for provenance and regeneration commands.
