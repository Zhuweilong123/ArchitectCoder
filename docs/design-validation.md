# 设计校验的模块边界

任务通过 `todo_write` 的 `validation_requirements: [{rule_id, diagram_name}]` 声明需要验收的注册检查。要求在本任务内累计，更新 todo 时不能删除，checkpoint 保存后恢复时继续生效。布局任务不必声明源码检查；源码一致性审查按图类型指南声明对应规则。工具描述不列举图类型专属字段。

验收策略在通用校验、设计审核和提交前重检时比较要求与实际报告。缺目标、缺规则、not_applicable、unavailable、unsupported 均不能满足要求；partial 仅当规则明确报告所声明范围的证据已核验时可满足。源码规则的整体行为限制不影响已核验范围，但部分出口、歧义证据和未验证顺序仍不满足要求。任务验收要求独立于设计契约开关，关闭实现契约检查不会清除已声明要求。没有修改文件的审查任务也执行声明的检查。

目前验证意图由结构化任务声明和指南衔接；系统不从任意聊天文本猜测必需检查，也不自动证明所有业务语义。未声明的旧任务保留原行为。规则结果负责 coverage_met，验收模块只比较注册规则，不依赖图或语言实现。

自动补推审核执行与显式审核相同的规则和任务覆盖检查。最终提交验收优先复用本轮契约报告；可选插件不提供报告时，Host 的 task_validation 模块执行同一公共校验入口，因此插件禁用不会导致必需检查被跳过。验收失败保留要求和诊断，任务恢复提示会带回原要求。

`run_task(validate)`、设计审核和设计契约检查通过共享校验入口执行内置规则；模型负责生成设计和按诊断修复，不生成用于替代这些规则的检测代码。

| 模块 | 职责 | 维护边界 |
| --- | --- | --- |
| `app/agent_base/host_api/validation.py` | 事实、规则、诊断和覆盖报告的公共协议 | 不依赖规则、插件或执行器 |
| `app/validation/engine.py` | Schema 检查及注册规则的分发 | 不解析语言，不决定审核或提交策略 |
| `app/validation/rules/` | 按图类型组织结构与语义规则 | 只消费设计数据和公共事实协议 |
| `extensions/design_contract/language_adapters.py` | 复用语言注册表，提取源码实体和控制流事实 | Python/Clang 各自维护，不依赖图规则 |
| `app/services/design_validation.py` | 装配默认规则和事实提供者 | 通过 Host API 访问可选插件 |
| `app/validation/policy.py` / `design_contract/contract_harness.py` | 审核策略 / 提交策略 | 各场景独立决定如何处理覆盖不足 |

增加图规则时实现 `ValidationRule` 并注册到装配层，无需修改工具描述或语言解析器。增加语言时实现现有语言适配器，输出统一 `SourceFunction/SourceOperation` 事实；已有图规则不随语言增加而修改。旧时序校验接口仅作为兼容包装保留。

当前有类图、组件图、时序图结构规则；源码控制流一致性规则目前针对时序图。类图实现/方法/测试映射仍由设计契约插件维护。通用框架不意味着所有图类型已拥有全部语义规则，也没有新增完整跨图行为证明。

报告列出每个检查及其覆盖：`checked`、`partial`、`not_applicable`、`unavailable`、`unsupported`。整体 pass 仅指已列出的适用检查无错误；未声明源码证据不代表源码一致性已验证。审核拒绝确定性错误，覆盖不足保留在报告中；契约提交检查还阻止请求的能力 unavailable/unsupported。只改设计文件也会检查设计规则，但不会因此要求新设计已有完整实现和测试。

源码驱动的时序图字段由图类型指南定义。Python 使用 AST，C++ 使用现有 Clang/Broker/编译配置。契约收集阶段保存本轮事实快照，规则复用该快照，避免同一文件重复解析；缓存仅限本轮检查，不跨修改复用。编译器不可用时报告覆盖不足，不假装验证通过。动态派发、异常、guard/返回值等价性和整体行为仍需审查。
